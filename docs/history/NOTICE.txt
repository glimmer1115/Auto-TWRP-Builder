SESSION HANDOFF - 2026-10-29 - Ramdisk compression clarification

확인된 커널 설정
- 사용자가 제공한 커널 설정에서 CONFIG_RD_GZIP=y이며 CONFIG_RD_BZIP2,
   CONFIG_RD_LZMA, CONFIG_RD_XZ, CONFIG_RD_LZO, CONFIG_RD_LZ4는 비활성화됨.
- 이 설정이 최종 recovery 이미지에 사용하는 커널의 정확한 설정이라면,
   커널이 지원하는 initramfs 압축 형식은 gzip으로 제한해야 한다. 최종
   ramdisk에 XZ를 사용하지 않는다.
- 설정의 정확한 커널/이미지 provenance는 실제 플래시 대상 이미지와 연결해
   확인할 것. 이 설정만으로 백라이트 지속 현상의 원인을 확정하지 않는다.

패키저 동작
- scripts/package_recovery.py는 입력 ramdisk를 gzip, XZ 또는 비압축 데이터로
   해제할 수 있고, 재패키징 출력은 RAMDISK_COMPRESSION 기본값 "gzip"을 사용함.
- 따라서 TeamWin 빌드 입력의 원래 압축 형식과 최종 recovery.img의 압축 형식은
   별개다. TeamWin 원본 압축 형식은 해당 이미지 ramdisk 매직을 직접 확인하기
   전까지 미확정으로 둔다.
- 기본 gzip 설정은 유지한다. 커널 설정과 다른 압축 출력 형식으로 바꾸지 않는다.

   OrangeFox workflow의 S-Boot ramdisk 제한은 계속 14,680,064 bytes다.

검증 상태와 남은 검증
- python scripts/test_package_recovery.py 통과(6 tests).
- python -m py_compile scripts/package_recovery.py scripts/test_package_recovery.py,
   workflow summary heredoc 구문 검사, VS Code diagnostics, git diff --check 통과.

   않았으므로 빌드 및 기기 동작은 미검증이다.
- TeamWin 입력 형식이 필요한 경우 실제 입력 이미지의 ramdisk 시작 바이트/매직을
   확인한다. 커널 설정이나 출력 압축 설정으로 원본 입력 형식을 추정하지 않는다.
