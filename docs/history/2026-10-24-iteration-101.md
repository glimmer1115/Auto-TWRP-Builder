# 101회차 빌드 스크립트 검토 및 보강 기록

- 날짜: 2026-10-24
- 대상 기기: SM-T583 (Exynos 7870, `gtaxladwifikx`)
- 검토 기준: [100회차 빌드 스크립트 수정 및 검증 기록](2026-10-24-iteration-100.md)

## 100회차 검토

- 100회차 `build.py` 수정은 입력 파일 및 필수 인수를 확인하고, 실제 출력 디렉터리에서 `Android.bp`를 찾으며, `GITHUB_OUTPUT`을 append 방식으로 기록하도록 개선했습니다.
- 후속 검토에서 장치명 검증 순서의 결함을 확인했습니다. 기존 코드는 이미지에서 얻은 manufacturer/codename을 `DeviceTree.dump_to_folder()`에 먼저 전달한 다음 검사했습니다. 입력 메타데이터가 경로 구분자를 포함하면 검증 전에 파일 쓰기가 일어날 수 있었습니다.
- 기존 검사는 경로 구성 요소 일부만 확인했으며 셸 명령에 그대로 삽입될 수 있는 공백·셸 특수문자도 허용했습니다. Legacy workflow는 `MAKEFILE_NAME`을 `lunch` 명령에 직접 사용하므로 장치 식별자 입력을 더 엄격히 제한할 필요가 있습니다.
- 99회차의 recovery ADB 실패와 화면 점등 증상은 정확한 플래시 이미지 해시 및 TWRP 실행 로그와 연결되지 않았습니다. 따라서 이 회차에서는 디스플레이, SELinux 또는 integrity 정책을 추정으로 변경하지 않았습니다.

## 이번 회차 수정

- `scripts/build.py`에서 manufacturer/codename이 비어 있지 않고 `[A-Za-z0-9_-]+` 형식인지 `DeviceTree.dump_to_folder()` 실행 전에 검증합니다.
- `None` 메타데이터는 문자열 `None`으로 통과하지 않고 빈 값으로 처리해 거부합니다.
- 안전하지 않은 값은 명확한 오류로 종료하며, 검증 실패 시 장치 트리 덤프를 실행하지 않습니다.
- 기존 절대 출력 경로 처리, `Android.bp` 확인, `GITHUB_OUTPUT` append 동작은 유지했습니다.

## 검증

- `python -m py_compile scripts/build.py`: 통과.
- 가짜 `DeviceTree` 실행 검사: 유효 메타데이터에서 `Android.bp` 및 실제 `DEVICE_PATH` 출력, 기존 `GITHUB_OUTPUT` 내용 보존을 확인했습니다.
- 경로 탐색값 `../outside` 검사: 오류 코드 2로 종료하고 `dump_to_folder()`가 호출되지 않으며 출력 트리 밖에 파일이 생성되지 않음을 확인했습니다.
- 로컬 Python 환경에 `twrpdtgen`이 설치되어 있지 않아 실제 recovery 이미지 변환은 실행하지 않았습니다. 전체 TWRP 빌드, GitHub Actions, 실기기 플래싱도 이 회차에서 수행하지 않았습니다.

## 대화 요약 및 중요한 결정

- 사용자는 100회차 기록을 검토해 빌드 스크립트를 분석·개선하고, 변경을 커밋한 뒤 알리며, 101회차 히스토리에 수정 사항과 중요한 대화 내용을 요약해 달라고 요청했습니다.
- 사용자는 `twamwin`의 SM-T580/SM-T585 `twrp.img`는 비교·참고용일 뿐이라고 명확히 했습니다. 해당 이미지를 SM-T583에 플래시하거나 SM-T583용 빌드 입력으로 취급하지 않습니다.
- 99회차 이후 보고된 백라이트 지속 점등과 recovery ADB 미연결은 기록하되, 순정 recovery 복원본 및 보존된 로그와 구분합니다. 해당 증상을 특정 TWRP 산출물의 원인으로 단정하지 않습니다.
- recovery ADB와 Android의 rooted ADB는 별도 결과로 기록합니다. `/sbin/adbd` integrity 거부, USB gadget bind, 화면 동작은 새 이미지의 해시와 해당 부팅 세션 로그를 확보한 뒤 순서대로 분석합니다.
- 로그 근거 없이 SELinux 완화, integrity 검사 해제, 밝기 코드 변경 또는 대기 시간 연장을 하지 않습니다.
