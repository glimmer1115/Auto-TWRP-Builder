# 112회차 분석 및 검증

- 날짜: 2026-10-26
- 대상 기기: Samsung SM-T583, Exynos 7870, `gtaxladwifikx`
- 기준 속성 블록:

```make
PRODUCT_DEFAULT_PROPERTY_OVERRIDES += \
    ro.secure=0 \
    ro.adb.secure=0 \
    ro.debuggable=1 \
    persist.sys.usb.config=adb
```

## 111회차 분석

- iteration-110 커널 로그에서 Recovery가 기록한 값은 `ro.debuggable=0`, `ro.secure=1`, `ro.adb.secure=1`, `persist.sys.usb.config=mtp`였습니다. 로그 대상 이미지의 Actions run ID, checkout SHA, 이미지 SHA-256은 없어 현재 코드와 해당 기기 이미지의 동일성은 확인되지 않았습니다.
- 저장소 워크플로는 이미 제품 makefile에 위 네 속성을 지정하고, 빌드 출력의 램디스크 `default.prop` 및 존재하는 `prop.default`를 검사하고 있었습니다. 따라서 원인을 특정 이미지에 속성을 주입하지 않은 문제로 확정할 수는 없습니다.
- 남아 있던 검증 공백은 제품 출력 검사 이후 Odin용 `recovery.img`를 다시 조립하는 패키징 단계였습니다. 최종 파일의 CPIO 램디스크 안에서도 `ro.debuggable=1`이 보존되는지 확인하지 않았습니다.

## 112회차 변경

- 워크플로 제품 속성 블록의 순서를 사용자가 제공한 인용과 일치시켰습니다. 핵심 항목 `ro.debuggable=1`은 유지합니다.
- Odin 패키저가 최종 이미지에 들어갈 gzip CPIO를 다시 읽어 루트 `default.prop`의 존재를 요구하고, 이 파일과 존재할 경우 `prop.default` 양쪽에서 네 속성의 최종값을 검증하도록 추가했습니다. 값이 누락되거나 달라지면 패키징 단계가 실패합니다.
- 검증은 재압축과 최종 boot image 조립에 사용되는 동일 램디스크 바이트를 대상으로 합니다. 실제 init/property 초기화 순서나 연결된 USB host까지 보장하는 검사는 아닙니다.

## 검증 및 미확인 사항

- 통과: 합성 newc CPIO의 기대값 `ro.debuggable=1`, `ro.secure=0`, `ro.adb.secure=0`, `persist.sys.usb.config=adb` 확인.
- 통과: 같은 CPIO에서 `ro.debuggable=0`으로 바꾼 음성 사례 거부.
