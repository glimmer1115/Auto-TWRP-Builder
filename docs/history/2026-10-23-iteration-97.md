# 97회차 빌드 수정 기록

- 기록 기준: 2026-10-22 ~ 2026-10-23 저장소 변경 이력
- 대상: SM-T583 (Exynos 7870) TWRP 리커버리

## 변경 내역

- Samsung 레거시 `android_usb` 경로로 USB 초기화 흐름을 정리했습니다. configfs를 비활성화하고, 패널 노드를 기다린 뒤 ADB 속성을 설정하고 `adbd`를 시작한 다음 gadget을 활성화합니다.
- FunctionFS descriptor 준비 시간은 recovery SELinux 도메인에서 `usbwait.sh`로 확보합니다. 대기 시간은 0~5초로 제한하며, 범위를 벗어나면 5초를 사용합니다.
- `patch_bringup.py` 자체 검사에 USB 설정, 초기화 순서, 대기 시간 상한 검증을 추가했습니다.
- `gui.cpp` 초기화 중 백라이트 sysfs를 직접 쓰던 코드를 제거하고 TWRP 밝기 설정을 사용합니다. `sm_mark`는 밝기 대신 `/cache/recovery/sm-stage`에 단계 기록을 남깁니다.
- Android 9 TWRP 트리에서 GUI 패치 대상 탐색이 불안정한 문제를 줄이도록 로컬 `gui.cpp`와 패치 흐름을 정리했습니다.

## 진행 방향

1. SM-T583 실기기에서 recovery 부팅, 화면 초기화, ADB 연결을 함께 확인합니다.
2. `/cache/recovery/sm-stage` 기록과 recovery 로그로 멈춤 지점을 확인하고, descriptor 대기 시간은 실제 연결 결과를 기준으로 조정합니다.
3. 실기기 로그로 문제가 재현되기 전까지 GUI 초기화의 직접 sysfs 쓰기와 USB 초기화 순서를 추가로 변경하지 않습니다.
4. `patch_bringup.py` 자체 검사를 유지해 Android 9 트리 호환성과 USB 초기화 순서의 회귀를 확인합니다.

## 실기기 결과

- 초기 화면에서 직전 회차와 같은 미세하고 짧은 깜박임이 연속해서 발생한 뒤, 백라이트는 계속 켜져 있고 recovery ADB는 연결되지 않았습니다.
- 이후 Android가 부팅된 상태에서 root ADB 연결을 확인해 RECOVERY 파티션을 읽기 전용으로 덤프했습니다. 원본 덤프와 로컬 파일의 SHA-256은 `4cfed1508346022a45dbc479aa657aeffad67d5ab5f68450d60eada4f6ced36d`로 일치했습니다.
- recovery boot image에서 16,989,448바이트의 ARM64 `Image` 커널을 추출했습니다. 결과물은 로컬 전용 `artifacts/iteration-97/recovery.img`와 `artifacts/iteration-97/Image`이며 원격 저장소에는 포함하지 않습니다.

## 다음 진행

커널 덤프는 확보했지만 recovery ADB 미연결 문제는 해결되지 않았습니다. 다음 분석은 화면 깜박임·백라이트 유지와 ADB 초기화 실패를 별도 신호로 보고, 추출한 recovery 이미지 및 기기 로그를 기준으로 부팅 단계를 대조합니다.

## 후속 수정

- 부팅 단계 표시용 `sm_beacon`, fault, GUI 마커가 밝기 sysfs에 진행 번호를 직접 기록하던 경로를 확인해 제거했습니다. 이제 `/cache/recovery/sm-stage`에만 기록합니다.
- 자체 검사에 생성된 TWRP·fault·GUI 마커가 밝기 노드를 쓰지 않는지 확인하는 회귀 검사를 추가했습니다. `self_test()` 통과를 확인했습니다.
- 98회차 수정 빌드 플래싱 결과 초기 깜박임은 사라졌고 recovery ADB는 여전히 연결되지 않았습니다. 밝기 비콘 제거가 깜박임 개선에 기여한 것으로 보이며, ADB 문제는 별도 원인으로 계속 조사합니다.
